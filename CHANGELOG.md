# Changelog

## 0.2.0 — unreleased
- Renamed to **Harness Offload** (`offload` CLI, `harness-offload` package). MIT.
- TypeScript engine (`harness-offload` npm package) alongside the dependency-free bash engine; shared conformance suite.
- Connectors: OpenCode v1/v2, Pi, Codex CLI, Gemini CLI, Cursor CLI, Claude Code, 16 HTTP presets (OpenAI-compatible + Anthropic) and custom endpoints; `BACKEND:MODEL` refs; fallback chains across backends.
- Hosts: Claude Code, Codex, Cursor, Gemini CLI, Pi, OpenCode, Devin/Windsurf, any MCP client (`offload mcp`).
- `offload setup` wizard, `offload install/uninstall <host>`, standalone binaries, install scripts, CI.
- **Same subscription by default:** `@host` resolves to the calling harness's own small model (Claude Code → Haiku via a lean `claude -p`, Codex → `codex exec`, Gemini CLI → Flash-Lite, Copilot CLI, Qwen Code and Crush as their own workers); defaults are `@host` then OpenCode's default model. The wizard asks this first. `-m MODEL` is used alone.
- The bash engine runs the agent-CLI connectors and HTTP APIs (curl) natively, so the Claude Code plugin works with bash + jq only; the TypeScript CLI is bundled inside the plugin (`dist/`, checked in CI).
- More harnesses: GitHub Copilot CLI, Qwen Code, Crush (verified with the real binaries), Aider (conventions file), MCP snippets for Cline, Zed, Continue, Goose, Kiro, VS Code and Claude Desktop.
- Security review fixes: untrusted project config (`offload config trust`), sandboxed explore tools (real-path containment, no symlinks, `.git` refused, regex deadline, caps), redaction of answers/command lines/log names, wider credential patterns, bounded citation checks, fail-open in-process plugins, process-tree cleanup, MCP limits and cancellation, Windows spawning without a shell. See SECURITY.md.
- `offload dashboard`: offline HTML report. Landing page in `site/`.
- **Your own tasks:** `tasks.<name>` in the config (user or repo) = your instructions + offload's citation rules, an optional model and `tools: none|read`; `offload task NAME [PATH…|--stdin]`, `offload tasks`, `offload_task` for MCP clients and Pi, listed in the session guide, checked by `offload doctor`.
- **`offload model`:** show and switch the model per kind of work in one command (`offload model groq:…`, `offload model read claude:haiku`, `--reset`, `--project`); references are checked first (unknown backend → "did you mean", missing model id) and missing keys/CLIs are flagged. `offload doctor` runs the same checks.
- **Every backend tested one by one** (`tests/e2e-backends.sh`, in CI): all 18 HTTP presets + custom endpoints against a mock (paths, auth headers, model ids, errors, model lists), the real provider URLs with a fake key, and the agent CLIs logged out. Fixes it found: Qwen "no auth type", Pi "no API key"/"invalid security token" and Crush "no providers configured" now map to exit 11 (were 14); Gemini's login error (JSON on stderr) is shown; `offload models BACKEND` reports HTTP errors instead of printing nothing; clearer hints for auth/model errors.
- **API-key backup for every harness:** `@host-api` = the harness's model family through an API key (Claude Code → `anthropic:claude-haiku-5-5`, Codex → `openai:gpt-6-luna`, Gemini CLI → `google:gemini-flash-lite-latest`, Qwen Code → `dashscope:qwen-flash`, Copilot CLI → `github:openai/gpt-4.1-mini`), skipped until a key exists. `offload setup` offers it as a backup or as the main route; `offload install` prints the one-liner; `offload key NAME` stores keys (hidden input, mode 600). New presets: Alibaba Model Studio (`dashscope`), GitHub Models (`github`).
- **Dashboard redesign** (the owner's pick, "Standard"): a calm dark report with number cards, an area chart (hover and keyboard focus show a guide, marker and tooltip beside the line; the unfinished current hour/day reads "so far"), tinted status pills, and the same table view, cooldowns and empty state as before. Fixes found on the way: hover never fired at a point's centre, any resize dropped the hover, the 24-hour view listed one hour twice and plotted the running hour as zero, model ids broke inside names on phones. The landing page keeps its current design. Then, at the owner's request, the report took the landing page's colour and type: the carbon-blue bar over cool paper (light by default, dark with the system), Archivo / Public Sans / Courier Prime embedded as small latin subsets so it still opens offline (licence notices in `LICENSE-FONTS`).
- The bash CLI forwards `setup`, `models`, `install`, `sync`, `mcp`, `demo` to the bundled TypeScript CLI (clear message when Node is missing).
- **Faster hooks** ([docs/performance.md](docs/performance.md), measured): a tool call that offload lets through now waits ~15–20 ms (Claude Code) or ~40 ms (Node hooks: Codex, Cursor, Gemini…) instead of 105–175 ms / ~105 ms; in real Claude Code a 17-call session gains +0.95 s instead of +4.4 s, with identical decisions. Bash: one `jq` for the input, one for the config (cached per project, keyed by the files' text), cheap checks before the availability probe, worker code loaded on demand, no 0.3 s polling after a worker answers. Node: hooks run from a 108 KB CommonJS bundle, the CLI is split into chunks, compile cache on, lazy built-ins. `OFFLOAD_DISABLE=1` answers in ~5 ms without starting Node. `hooks.digest_timeout_seconds` defaults to 20 s (was 90; `0` = instant digests). New `bench/hooks.mjs` (in CI, with a latency budget) and `bench/claude-e2e.sh`.
- Fixed: the plugin's bundled `dist/` had no `"type": "module"` marker, so on Node 18 / early Node 20 its Node hooks failed silently.
